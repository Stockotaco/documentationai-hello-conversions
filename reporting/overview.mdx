title: Reporting
description: What each report in Hello Conversions measures, which connected source it needs before it shows a number, and how date ranges and filters behave across the section.

**A report stays blank until the source it reads from is connected and has synced.** Reporting is the read-only half of a project: every figure is derived from what your sources send, no report has its own settings, and none can show a number the source never sent.

## What's in the section

| Group | Report | What it answers |
| --- | --- | --- |
| **Revenue** | [Overview](/reporting/revenue-overview) | What did we collect, from how many customers, over this window? |
| | [Lead LTV](/reporting/lead-ltv) | What is a lead captured this month worth 1, 7, 30, 90 days later? |
| | [Marketing Efficiency](/reporting/marketing-efficiency) | What did we spend, what came back, and per channel and campaign? |
| **Meta Ads** | Creatives | Per-creative spend and performance from the Meta Ads source. |
| | Frameworks | The same creative data grouped by creative framework. |
| | Tracking | Whether your Meta ads carry the tracking they need. |
| **Email** | Email Stats | Sends, opens, clicks and health for GoHighLevel email. |
| **Workflows** | Overview | Delivered, failed and filtered conversion volume. |
| | Activity Log | One row per delivery attempt, for tracing a single event. |

**Revenue → Overview** is the default landing page. The Workflows pair reads from the conversion-delivery pipeline rather than a warehouse, so those two populate as soon as a [connection](/conversion-tracking/connections) starts producing runs — [Activity & Run History](/conversion-tracking/activity-history) covers them in detail.

## What each report needs connected

Everything under Revenue, Meta Ads and Email is built from what your [sources](/connect/sources-vs-destinations) sync.

| Report | Needs | Without it |
| --- | --- | --- |
| **Revenue → Overview** | A revenue source: [GoHighLevel](/connect/sources/gohighlevel) or [Stripe](/connect/sources/stripe) | No revenue, customer or transaction figures |
| | GoHighLevel, for the form and product panels | Forms, Landing Pages and Products stay empty |
| | The [tracking script](/help-center/guides/install-tracking-script) | Page views, unique visitors and conversion rate stay at zero |
| **Lead LTV** | GoHighLevel — both contacts and transactions | The report can't be built at all |
| | [Meta Ads](/connect/sources/meta-ads) / [Google Ads](/connect/sources/google-ads) | Leads and revenue still work; spend, CAC, payback and LROAS are blank |
| **Marketing Efficiency** | GoHighLevel — both contacts and transactions | No leads, no sales, no customer classification |
| | Meta Ads / Google Ads | Spend, MER, CAC, and the whole campaign table are empty |
| **Meta Ads** (all three) | Meta Ads | Nothing to show |
| **Email Stats** | GoHighLevel | Nothing to show |

<Callout kind="warning">
  **Stripe alone is not enough for Lead LTV or Marketing Efficiency.** Both tie revenue back to the contact who produced it, and Stripe charges arrive without a contact link. A Stripe-only project shows an explicit "Stripe-only — Lead LTV unsupported" chip rather than silently reporting zeros. Revenue → Overview does work on Stripe alone, built directly from Stripe charges.
</Callout>

With both connected, Revenue → Overview uses Stripe as the truth for money it processed, matched to the GoHighLevel transaction sharing its payment intent, and GoHighLevel for anything Stripe never saw — cash, other processors, and the contact attribution.

## Date ranges

All three Revenue reports default to **the last 30 days**; Revenue → Overview also offers 7d / 30d / 90d shortcuts.

- **Days are cut in the project's timezone**, not yours and not UTC. A sale at 11pm on the 31st in a project set to `America/New_York` belongs to the 31st, even if you're reading in London. Set it under **Settings → Project → General**.
- **The comparison period is the same length, immediately before.** Pick 12 days and every trend arrow compares against the 12 days before that — not last month, not the same period last year.

Revenue → Overview and Marketing Efficiency also have a day / week / month granularity toggle, which changes how the chart and breakdown table bucket the data, not the window.

## Filters

Revenue → Overview has no filters beyond the date range. Lead LTV and Marketing Efficiency both filter on attribution:

| Filter | What it does |
| --- | --- |
| **Attribution: Last Touch** (default) | Attribute each lead to their most recent source, medium and campaign. |
| **Attribution: First Touch** | Attribute each lead to the source they originally arrived through. |
| **Source / Medium** | Restrict to leads whose resolved source or medium matches. |
| **Form** | Restrict to leads whose first-ever form submission was this form. |
| **Campaign** | Restrict to leads attributed to this campaign (Marketing Efficiency only). |

Marketing Efficiency lets you pick several values per filter; Lead LTV takes one of each.

<Callout kind="tip">
  Lead LTV keeps its full filter state in the page URL and has a **Copy link** button, so the recipient opens exactly the view you were looking at. If a link is old enough that its filters no longer match any lead in the window, an amber banner says so rather than showing an unexplained empty report.
</Callout>

## Freshness

| Report | How current |
| --- | --- |
| **Revenue → Overview** | Queried on demand, with results cached for 15 minutes to an hour depending on the panel. |
| **Lead LTV** | Built from a snapshot rebuilt once a day, in the project's local timezone. |
| **Marketing Efficiency** | Spend and lead data from that same daily snapshot; sales figures queried live. |

Lead LTV and Marketing Efficiency each show a **Data as of …** chip with the last successful rebuild time, and a **Refresh failed** chip if the most recent attempt errored — in which case you're looking at the previous good snapshot, not at nothing.

<Callout kind="note">
  The refresh button re-runs the report's queries against the current snapshot. It does not rebuild the snapshot, so a figure that's stale because yesterday's rebuild failed won't move until the next rebuild succeeds.
</Callout>

A report can only be as current as the last source sync — if ad spend looks a day behind, check the source before you suspect the report.
