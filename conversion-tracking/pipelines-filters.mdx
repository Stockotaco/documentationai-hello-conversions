"How many leads did we get?" only has an answer once you've decided what a lead *is*. In GoHighLevel that's usually a pipeline stage. Purchases are different — they come from order and transaction events rather than the pipeline.

## Leads and bookings: pipeline stages

**Settings → Workflows → Pipelines** pulls the pipelines and stages live from the connected Lead Connector (GoHighLevel) account. The header tells you how many stages are active out of the total, and each stage is a row you can switch on.

<Steps>
  <Step title="Find the stage">
    Search matches on pipeline name, stage name, or event name. The pipeline dropdown narrows to specific pipelines, **Active Only** hides everything switched off, and the sort control orders stages by pipeline order, alphabetically, or active-first. **Collapse all** makes the page usable on a client with a lot of pipelines.
  </Step>
  <Step title="Name the event">
    Each stage gets an event name, pre-filled from the stage name in lowercase with underscores — `Call Booked` becomes `call_booked`. This is what the destination receives, so change it to whatever the ad platform should see (`Lead`, `Schedule`, `Purchase`). A pencil icon marks a customized name.
  </Step>
  <Step title="Choose the value">
    **Opp. Value** sends the opportunity's own monetary value from GoHighLevel — right when opportunities carry realistic amounts. **Custom** applies one fixed value to every conversion at this stage — right when the pipeline value is empty or aspirational.
  </Step>
  <Step title="Switch the stage on and pick destinations">
    Flip the toggle and a **Send events to** row appears listing the project's connected destinations. Select every one that should receive this stage; with none selected the page warns you, and the stage does nothing.
  </Step>
  <Step title="Set the Google Ads conversion action">
    Google Ads destinations get a gear icon on their card. Google keys on a conversion action rather than an event name, so open it and pick which action this stage maps to. An amber dot means none is selected yet.
  </Step>
  <Step title="Save">
    **Save Changes** in the unsaved-changes bar applies everything at once; **Discard** reverts to the last saved state.
  </Step>
</Steps>

**Enable All** in a pipeline's header switches every stage in it on or off at once.

<Callout kind="warning">
  Switching on every stage sends a conversion at each step of the journey — one contact moving through five active stages produces five conversions. If you're feeding an ad platform's optimization, pick the one or two stages that represent the outcome you're buying.
</Callout>

### What a stage fires on

An active stage sends its event when an opportunity **arrives at that stage** — both when one is created directly in it and when an existing one is moved into it.

Behind the scenes this builds a connection listening for Opportunity Changed, filtered to that one pipeline and stage. Stage-managed connections deliberately don't appear on the [Connections](/conversion-tracking/connections) screen, because hundreds of stages would bury the connections you built by hand. What they deliver still shows up in the [Activity Log](/conversion-tracking/activity-history).

<Callout kind="note">
  If a project's pipelines don't load, Lead Connector isn't connected for that project — fix that under **Settings → Integrations → Sources**. Likewise, if no destinations appear under a stage, none are connected yet.
</Callout>

## Purchases

Purchases come from GoHighLevel's order and transaction events, wired up as ordinary connections: pick **Made Any Purchase**, **Product Purchased**, **Subscription Started**, or **Subscription Rebilled** as the source event and point it at a destination. Which to use, and how the three differ in timing and coverage, is in [Event Types](/conversion-tracking/event-types).

## Filters

Every connection can carry filter rules. A rule is a **field**, an **operator**, and a **value**; an event that fails is recorded as **filtered** and nothing is sent. With two or more rules you get a logic toggle: **AND** (the default) requires every rule to pass, **OR** requires any one.

<Callout kind="tip">
  Filters are also a diagnostic. Filtered runs appear in the Activity Log with the reason attached, so if a client insists a conversion should have fired, you can show them which rule stopped it.
</Callout>

### Which fields you can filter on

The available fields depend on the source event, because the fields only exist on those events.

| Source event | Fields you can filter on |
| --- | --- |
| Made Any Purchase | Monetary Value (number), Funnel Name, Funnel ID, Facebook Click ID, Google Click ID |
| Product Purchased | Product Name, Funnel Name, Funnel ID, Amount (number), Facebook Click ID, Google Click ID |
| Opportunity Changed | Pipeline Name, Pipeline ID, Stage Name, Stage ID |
| Tag Added | Tag Name |
| Tag Removed | Tag Name |
| Contact Created | Contact Source, Session Source |

<Callout kind="note">
  Subscription Started and Subscription Rebilled have no filter fields — the list will be empty. They're already narrowed by their own definition (a charge with a subscription attached, split by whether it's the first charge or a rebill), so filter them by choosing the right one of the two.
</Callout>

### Operators

| Operator | Works on | Notes |
| --- | --- | --- |
| equals / not equals | text, numbers | Exact match. |
| greater than / greater than or equal | numbers | |
| less than / less than or equal | numbers | |
| contains / does not contain | text | Case-insensitive. |
| exists / does not exist | text, numbers | No value needed — checks the field is present and not empty. |
| is one of / is not one of | text | Takes a comma-separated list. |

As you type a value, Hello Conversions suggests real values it has seen on that field in this project's recent events. You can always type one that isn't listed.

### Examples

**Only count opportunities that reach one stage**, on a connection with the source event **Opportunity Changed**. Add a second rule with AND logic if two pipelines share the stage name:

```
Pipeline Name  equals  Aesthetics – New Patients
Stage Name     equals  Call Booked
```

**Ignore small orders**, on a connection with the source event **Made Any Purchase** — useful when a client sells both a cheap tripwire and a high-ticket offer through one funnel:

```
Monetary Value  greater than or equal  500
```

**Only send purchases that came from ads**, or **group several funnels onto one connection** with *is one of*:

```
Facebook Click ID  exists
Funnel Name  is one of  Free Guide, Webinar Reg, Quiz Funnel
```

<Callout kind="warning">
  Filters match the event's fields exactly as GoHighLevel sends them, so a renamed pipeline stage silently stops matching a rule that names it. Filtering on **Stage ID** or **Pipeline ID** survives renames — less readable, but it doesn't break when a client tidies up their pipeline.
</Callout>
