---
title: How Delivery Works
description: The path a GoHighLevel event takes from firing in your client's account to landing in Meta or Google Ads, and what each delivery outcome means.
---

When a lead books a call or a customer buys, that happens inside GoHighLevel and your ad platforms never see it. Hello Conversions watches the events in the connected Lead Connector (GoHighLevel) account and forwards the ones you care about. Everything is scoped to a **project**: its own Lead Connector connection, destinations, rules and activity history, with nothing crossing between projects.

## The path an event takes

<Steps>
  <Step title="Something happens in GoHighLevel">
    A contact is created, an opportunity moves stage, a tag is applied, an order completes. GoHighLevel emits an event.
  </Step>
  <Step title="Hello Conversions recognizes the event">
    It's matched to one of the source event types we understand — Made Any Purchase, Opportunity Changed, Tag Added, and so on. Anything that doesn't map is ignored immediately. See [Event Types](/conversion-tracking/event-types).
  </Step>
  <Step title="It finds the connections that want it">
    A **connection** wires one source event to one destination. Every enabled connection in the project listening for that event picks it up; if none do, the event stops here and nothing is recorded.
  </Step>
  <Step title="Filters decide whether it counts">
    An event that fails a connection's filter rules — only this pipeline stage, only orders above an amount, only a specific tag — is marked **filtered** and never leaves the platform. See [Pipelines & Filters](/conversion-tracking/pipelines-filters).
  </Step>
  <Step title="The person and the click are matched up">
    The event is enriched with what we know about that person: email, phone, name, address, the Meta click ID (`fbc`/`fbp`), the Google click ID (`gclid`), UTMs, IP and user agent. The more of these, the better the ad platform can match the conversion back to a click. See [Match Quality](/conversion-tracking/match-quality).
  </Step>
  <Step title="It's delivered to the destination">
    The enriched event is reformatted into what the destination expects — a Meta Conversions API payload, a Google Ads conversion upload — and sent. The result is written to the Activity Log as a **run**.
  </Step>
</Steps>

One event can produce several runs: three matching connections means three runs, each succeeding or failing on its own.

## How fast it happens

Events flow continuously — no nightly batch, no "sync" button. Delivery is normally attempted within seconds, and each run records how long the delivery call took, in milliseconds. Two things delay an event:

- **Subscription events lag.** Subscription Started and Subscription Rebilled ride on GoHighLevel's transaction event, which arrives later than the order event a one-off purchase uses. See [Event Types](/conversion-tracking/event-types).
- **Failures are retried** several times with increasing backoff before being given up on.

## What each outcome means

| Status | What happened |
| --- | --- |
| **Delivered** | The destination accepted the request. |
| **Filtered** | The event matched a connection's event type but didn't pass its filter rules, or there was nothing usable to send — so no request was made. This is a normal, healthy outcome, not an error. |
| **Failed** | A request was made and the destination rejected it, or the destination was temporarily circuit-broken. |

The Activity Log's success rate counts **delivered plus filtered** as success, because a deliberately filtered event is the system doing its job.

### What "delivered" does and doesn't tell you

Delivered means the destination's API accepted the payload — not that the platform credited the conversion to an ad. **Meta** receives the event immediately, but attribution depends on how well the person matched a Meta user and on the attribution window. **Google Ads** accepts conversions for asynchronous ingestion, so an accepted upload only means "received"; we record the request ID and reconcile the real per-event outcome afterwards.

If a client says "you show 40 conversions and Meta shows 31", delivered-vs-attributed is usually the reason, not a delivery bug. Start with the [Activity Log](/conversion-tracking/activity-history).

## Duplicate protection

The same event is only ever sent to the same connection once — a redelivery from GoHighLevel or an internal retry is dropped. This is per event and per connection: it does **not** stop you double-counting by wiring two overlapping source events to the same destination, which is covered in [Event Types](/conversion-tracking/event-types).

## When a destination goes down

After five consecutive failures, sending to that destination stops for five minutes, then one request is let through to test recovery. Runs during that pause are recorded as failed with a circuit-breaker message — which is why an expired Meta access token shows up as a wall of failures rather than a trickle.
