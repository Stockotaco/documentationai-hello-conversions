---
title: How Delivery Works
description: The path a GoHighLevel event takes from firing in your client's account to landing in Meta or Google Ads, and what each delivery outcome means.
---

When a lead books a call or a customer buys, that action happens inside GoHighLevel. Your ad platforms never see it — which is why Meta optimizes against pageviews and Google reports conversions you can't tie to revenue. Hello Conversions closes that gap: it watches the events in the connected Lead Connector (GoHighLevel) account and forwards the ones you care about to the ad platforms.

This page is the mental model. Once you have it, the rest of this section is just the settings screens.

## Everything is scoped to a project

A **project** is one client account — or just your business, if you're not an agency. Each project has its own Lead Connector connection, its own destinations, its own rules, and its own activity history. Nothing crosses between projects.

## The path an event takes

<Steps>
  <Step title="Something happens in GoHighLevel">
    A contact is created, an opportunity moves to a new stage, a tag is applied, an order completes. GoHighLevel emits an event for it.
  </Step>
  <Step title="Hello Conversions recognizes the event">
    Each raw GoHighLevel event is matched to one of the source event types Hello Conversions understands — Made Any Purchase, Opportunity Changed, Tag Added, and so on. Events that don't map to anything are ignored immediately. See [Event Types](/conversion-tracking/event-types) for the full list.
  </Step>
  <Step title="It finds the connections that want it">
    A **connection** wires one source event to one destination. Hello Conversions looks up every enabled connection in the project that listens for that event. If none do, the event stops here and nothing is recorded.
  </Step>
  <Step title="Filters decide whether it counts">
    Each connection can carry filter rules — only this pipeline stage, only orders above a certain amount, only a specific tag. An event that fails the rules is marked **filtered** and never leaves the platform. See [Pipelines & Filters](/conversion-tracking/pipelines-filters).
  </Step>
  <Step title="The person and the click are matched up">
    Before sending, Hello Conversions enriches the event with everything it knows about that person: email, phone, name, address, the Meta click ID (`fbc`/`fbp`), the Google click ID (`gclid`), UTMs, IP and user agent. The more of these it can attach, the better the ad platform can match the conversion back to an ad click. See [Match Quality](/conversion-tracking/match-quality).
  </Step>
  <Step title="It's delivered to the destination">
    The enriched event is reformatted into whatever the destination expects — a Meta Conversions API payload, a Google Ads conversion upload — and sent. The result is written to the Activity Log as a **run**.
  </Step>
</Steps>

One event can produce several runs. If three connections match the same event, you get three runs — one per connection — and each one succeeds or fails on its own.

## How fast it happens

Events flow continuously. There is no nightly batch and no "sync" button to press: an event is picked up as it arrives and delivery is normally attempted within seconds. Each run in the Activity Log records how long the delivery call itself took, in milliseconds.

Two things can make an event show up later than you expect:

- **Subscription events lag.** Subscription Started and Subscription Rebilled ride on GoHighLevel's transaction event, which arrives later than the order event a one-off purchase uses. See [Event Types](/conversion-tracking/event-types).
- **Failures are retried.** A failed delivery is retried several times with increasing backoff before it's given up on, so a run that eventually succeeds may be a minute behind the event.

## What each outcome means

Every run ends in one of three states, and you'll see all three in the Activity Log and on the Workflows Overview.

| Status | What happened |
| --- | --- |
| **Delivered** | The destination accepted the request. |
| **Filtered** | The event matched a connection's event type but didn't pass its filter rules, or there was nothing usable to send — so no request was made. This is a normal, healthy outcome, not an error. |
| **Failed** | A request was made and the destination rejected it, or the destination was temporarily circuit-broken. |

The Activity Log's success rate counts **delivered plus filtered** as success, because a deliberately filtered event is the system doing its job.

### What "delivered" does and doesn't tell you

Delivered means the destination's API accepted the payload. That is not the same as the platform crediting the conversion to an ad.

- **Meta** receives the event immediately, but whether it attributes it to a campaign depends on how well the person matched a Meta user, and on the attribution window.
- **Google Ads** accepts conversions for asynchronous ingestion, so an accepted upload only means "received". Hello Conversions records the request ID and reconciles the real per-event outcome afterwards.

If a client says "you show 40 conversions and Meta shows 31", delivered-vs-attributed is usually the reason, not a delivery bug. Start with the [Activity Log](/conversion-tracking/activity-history) to confirm the events left the platform.

## Duplicate protection

The same event is only ever sent to the same connection once. If GoHighLevel redelivers an event, or something is retried internally, the duplicate is dropped rather than sent twice. This protection is per event and per connection — it does **not** stop you from double-counting by wiring two overlapping source events to the same destination. That's a configuration decision, and it's covered in [Event Types](/conversion-tracking/event-types).

## When a destination goes down

If a destination fails repeatedly — five consecutive failures — Hello Conversions stops sending to it for five minutes, then lets one request through to test whether it has recovered. While that pause is on, runs to that destination are recorded as failed with a circuit-breaker message.

This is why an expired Meta access token shows up as a wall of failures rather than a trickle: everything to that destination fails, the circuit opens, and it stays that way until the credentials are fixed.

## Where to look in the app

| Screen | Where it lives | Use it for |
| --- | --- | --- |
| **Overview** | Reporting → Workflows → Overview | Volume, delivered/failed/filtered totals, and the most common errors over 24h, 7d, or 30d. |
| **Activity Log** | Reporting → Workflows → Activity Log | Tracing one specific event end to end. |
| **Connections** | Settings → Workflows → Connections | Wiring source events to destinations. |
| **Pipelines** | Settings → Workflows → Pipelines | Turning pipeline stages into conversions. |
